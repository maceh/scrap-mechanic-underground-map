POC notes — fixed vs. approximated vs. descoped

Fixed, no variation: elevator at (-1,-1,2); the 3 cave "stack" slot positions/rotations — S(-1,-7,rot2), W(-5,-6,rot1), E(4,-6,rot3). All 3 possible slot configs sum to the same total height (8 chunks) — a real design constraint, not a coincidence.

Approximated (labeled, not exact): WHICH config lands in which slot. Inferred from a naming-pattern analogy elsewhere in the script (shuffle(array, startIndex) leaves items before startIndex untouched) that config[1] (the single "8" tile) is always fixed to slot S, while only the two 2-piece pairs shuffle between W/E. This is an inference, not confirmed. Per-tile micro x/y offsets are approximated the same way.

Descoped, not modeled: exact bedrock-bevel geometry (formula known, but depends on this depth's real xMin/xMax/yMin/yMax bounds — not available in any file reviewed); pockets, tunnel pockets, and real tunnel pathing — all defined in the ~1800-line section of terrain_underground.lua not yet read. Reading that section is the clear next step before this depth's map can include tunnels.next step, not silent gap
